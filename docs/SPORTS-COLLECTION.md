# Gesture sports contract

Darts, Archery, Basketball and Cup Pong render original perspective SVG arenas with depth, lighting and physical trajectories. This is projected 3D presentation, not a WebGL renderer or copied GamePigeon artwork. Two to four players compete over the existing peer connection.

Primary play uses pointer capture for touch or mouse. Start in the projectile area, lift/flick upward and release to throw; Archery pulls downward against the bowstring and releases. Held projectiles follow the pointer. Distance, direction and gesture duration map to finite physical launch inputs. Cancellation, lost capture, Escape, window blur and hidden tabs discard the gesture. A collapsed keyboard/precision disclosure provides labelled range controls and a release action as a non-drag alternative. Reduced motion skips replay.

Darts, Archery and Cup Pong retain six interleaved throws per player. Each player gets an identical independent cup rack and shared seeded archery wind. Basketball sportVersion 2 instead gives each player a sequential 60-second round, repeated lift-and-flick shots and two points per basket. Start my 60 seconds is an explicit readiness action; throwing needs no separate button. Acknowledgement plus 350 ms cooldown prevents duplicate/overlapping requests without waiting for a full trajectory replay. A four-second unacknowledged request allows retry with a connection notice.

Basketball moves are start-round, physical shot with elapsed milliseconds, or finish-round with elapsed exactly 60000. The group host must stamp elapsed with its own monotonic round clock and invoke finish at the deadline even if no more shots arrive. Client elapsed is a display hint only. Pure rules require an active round, elapsed [0,60000), at least 350 ms between accepted shots and at most 120 shots per player. The host decides when the buzzer fires; foreground/background suspension and reconnect behavior belong to the group service. Payload stays constant size: scores, shot counts, completed flags and last physical shot, never a growing shot history. A malicious trusted host can cheat; this is a friendly contest, not a ranked anti-cheat system.

Physical inputs are aim [-1,1], elevation [5,75] degrees and strength [0,1]. Lower target launch angles correct the prior 20-degree lower bound which made central darts impractical. Fixed 240 Hz semi-implicit integration, quantized velocities/positions, gravity, target rings, sphere/rim reflections, backboard restitution and table bounces derive scores. No client score is used. Version-one six-shot snapshots remain valid; new matches use sportVersion 2 and collection protocol 3.

No new packages, backend endpoints, storage, private data, or cloud costs. Simulation is capped at six seconds/362 path points; listeners and animation frames clean up. Scaling remains the existing small peer group model. No spin/aerodynamic-drag claim. Verify deterministic trajectories, gesture mapping, pointer cancellation, timed boundaries, shot cap, score derivation, equal opportunities, stale/unauthorized group moves and real touch feel. Browser/device visual review and actual PC-phone latency testing must be reported separately from automated checks.
