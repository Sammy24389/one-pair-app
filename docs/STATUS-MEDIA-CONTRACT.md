# Status media and paired-user feed

Outcome: one Status screen shows active updates from every current pair. New posts are explicitly shared with all current pairs; each pair receives only the local author's posts, never another contact's feed. Existing pair-specific posts keep their original audience. New pairs do not receive old posts automatically.

Text remains compatible. Optional image/video records carry local binary IDs, MIME and size. Photos accept JPEG/PNG/WebP up to 10 MiB; videos MP4/WebM up to 25 MiB. Captions allow 500 characters. Five active posts, 24-hour visibility, no public URLs, no autoplay. Publisher stores one blob, then publishes matching references into each current pair document after readiness and capacity validation. Delete removes local-author copies across current pairs. Offline transfer resumes using the existing missing-media protocol. Loading, invalid-file, storage-error and playback-error states must be visible.

Affected layers: React screen, Yjs documents, IndexedDB binary storage, authenticated pair transport and tests. No new API, cloud storage, auth, database schema, dependencies or operating resources. Existing Vercel/Capacitor runtimes apply. Trust remains the existing pair secret. Expiry removes feed visibility; downloaded media follows existing device media retention and can remain on disk after expiry. Automatic binary garbage collection is out of scope because shared media requires reference-safe cleanup. Scaling remains bounded by five posts per author per pair; total contacts and external rendezvous availability retain existing constraints. Deployment/APK rebuild are not part of this implementation request.

Verification: metadata limits/negative cases, media-only posts, all-pair publishing and deduplication, privacy boundaries, deletion, remote media request/arrival, composer selection/cancellation/error states, responsive media sizing, typecheck, full suite, web and Android asset builds. Real mobile playback and transfer still require device checks.

Verified: typecheck, 134 tests across 21 files, Android web-assets build, production PWA build and diff checks pass. No ESLint configuration exists. Real Status component tested in an isolated local fixture with two synthetic pair documents: photo selection, preview, IndexedDB save, publication, author deduplication and loaded image display work. At 390px and 1280px there was no horizontal overflow; measured buttons were 42px or 46px tall. No page console errors. Video controls/error/retry are regression-tested; actual phone codec compatibility and PC/phone transfers remain unverified. No production deployment, commit or APK assembly performed for this change.

Cause and prevention: Status previously read only useActiveSpace and had no binary references. The combined feed subscribes to every current pair; tests assert no cross-contact relay and one own card despite per-pair copies. Media uses existing committed local storage before metadata publication, then the receiver requests the missing bytes. Keep these boundary tests when changing the feed or transport.

Pragmatist review: usable for another device test with clear sharing audience, previews and bounded files. Strict review: verify real phone video codecs and transfer/reconnect; expired downloaded media still consumes local storage. Rollback: revert this feature before publication; legacy text records remain readable and newer media posts should be treated as requiring the newer app.
