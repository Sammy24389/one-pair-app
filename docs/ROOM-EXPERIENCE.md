# Rooms, shared playback and call alerts

Outcome: up to four connected people can play, chat, call and watch/listen without chat covering the game. Sections are Games, Chat and Watch & listen. Calls remain independent floating overlays; an incoming online group call produces an actionable toast/system notification and a selected in-app tone. Voice/video joining always requires an explicit action.

Watch together streams one participant's local video/audio playback over the existing authenticated encrypted WebRTC room. Host controls pause and seeking; receivers explicitly join audio. Files stay on the host device; no upload server or persistent copy. Input limited to1GB, live output up to1280x720/24fps; up to three recipients. Screen capture uses the browser permission picker, stops on system capture end, and is available only when getDisplayMedia exists. The Android APK originates screen capture through the native MediaProjection bridge after explicit consent. Protected streaming content may block capture; shared system audio availability is browser dependent. Android capture is video-only at up to10fps; conversation audio continues through the call microphone. Mobile browser capture still depends on browser support.

Notification tones: Chime/Bell/Soft/Silent for in-app messages and calls, persisted and previewed in Appearance settings. Android uses a bounded set of tone-specific channels backed by bundled original WAV files; OS channel overrides still take precedence. Silent/sounds-off suppresses sound and vibration. Online/background reachability uses existing Android service; a closed/suspended browser cannot be guaranteed to receive calls without push infrastructure. Call notices rate limited to one per room15 seconds, event ingress60/10seconds per authenticated peer; malformed/nonmember events ignored. Share metadata bounded80characters; single presentation per sender; group maximumfour. Existing room invitation/auth contracts retained. No new public API, accounts, database migration, cloud storage, Docker or worker introduced. Local300-message retention retained. No additional dependency. CDN hosts only static app, all private streams P2P.

Race to21 is removed from the new room catalog because its solved opening strategy rewards order; protocol retained for compatibility. Sports scoring changes require updating all players together. Existing host trust and network delays remain; this is friendly play, not a cheat-resistant competitive service. Scaling behavior unknown beyond the existing four-device cap — production risk. Network/codec/permission failure produces visible error and stops owned tracks/context/render callbacks; leaving room stops presentation. Sharing has a generation guard so canceled preparation cannot resurrect capture. Rollback is source revert; no data migration.

Verification: typecheck, full Vitest suite, production/PWA and Android web builds; responsive rendered UI, drag sports/crop gestures, movie/music source selection and playback checks. Physical two-device audiovisual timing, mobile CPU/battery, native notification sound, and desktop OS screen-picker permissions require device testing; do not infer from unit tests. Backend/RLS/index/query-plan/queue/rate-limited HTTP endpoints are not applicable to this peer-only change. External signaling/TURN availability and capacity remain outside app control.

Recovery regression: reconnect originally considered only microphone/camera calls busy, so losing the last peer could select a live presentation for teardown. Presentation ownership now marks the room busy in both recovery selection and reconnect itself. Two regression tests prove screen/media tracks stay live during temporary peer loss and recovery resumes after sharing stops.
