# Profile and sticker media

Outcomes: select a display photo or short muted looping profile video; crop still images before saving stickers; preserve animated stickers and support short silent video stickers; document manual WhatsApp file import. Existing photo profiles and saved static stickers remain readable.

Design: profile media picker with loading/error/removal and emoji fallback. Videos stored once in device IndexedDB, referenced by profile metadata in each pair doc, never embedded in localStorage/Yjs. Profile video max5 MB/15 seconds/720p (up to1280x720 in either orientation). Cropping shows square preview, zoom and horizontal/vertical controls, Crop and add / Keep full image / Cancel, plus keyboard/focus handling. Animated files bypass crop so frames are preserved. Sticker library previews preserve the selected media format; received stickers retain Add to stickers. Format/size/dimension/duration limits enforced before committed storage.

Sticker bounds: static image input10 MB, decoded16MP, output512px/512KB; animation2 MB/512px preserved; video5 MB/15sec/720px; 32 items/32 MB library. Photos profile10 MB compressed. Local crop/re-encode means original file is unchanged. Imported files are copies. No WhatsApp account access, scraping, clipboard extraction or proprietary pack parser; import individual exported/shared WebP/GIF/PNG/JPEG/MP4/WebM files only. File availability differs by platform.

Affected: React profile/picker/chat, IndexedDB blobs/library, Yjs profile references, existing authenticated pair media transport, static hosting/Capacitor builds. No backend/API/cloud storage/schema migration/dependency required. Media delivery requires concurrent online peers; old clients need updating for videos. Downloaded blobs follow existing local media retention; deletion from library/profile need not erase copies already sent. Repeated profile changes can grow local media storage; reference-safe global cleanup stays outside this slice. Verify limits, signatures, animation preservation, crop geometry/cancel, rendering and save failure states, paired transfer, backwards compatibility, full tests/typecheck/build, CI, deployment smoke and APK signature/integrity/provenance. User authorized commit/deploy/rebuild and existing APK assets must be retained.

Verification: typecheck and all162tests across26files pass; Android web-assets and production PWA builds pass. No ESLint configuration or new dependencies. Isolated real-component browser fixture at390px: MP4 display profile stored and played muted/looping; still image crop preview/zoom/save worked; GIF imported without crop; MP4 sticker imported, played muted/looping when visible and saved from a received-message view. No horizontal overflow or page console errors. Actual Android file-manager access, codec behavior and phone-to-phone transfer remain device checks; automated transport regression covers member-only profile reference recovery.

Cause/prevention: the old static canvas path discarded animation frames; inspection now separates still/animated/video before encoding. Crop editor uses a bounded source square and keeps animation outside that path. Profile video bytes stay outside identity/Yjs; validated references reuse pair media recovery. Compatibility tests preserve existing photos and old saved-sticker shapes.

Pragmatist review: ready for release with explicit bounds and file-import guidance.
